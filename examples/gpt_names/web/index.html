Zig 领先的来源：反传内核 linear_bwd_x / linear_bwd_w / rmsnorm_bwd 由标量循环改写为 8-lane @mulAdd FMA，嵌入相加与梯度范数（sumsq）同样向量化，Adam 的偏置校正项移出内循环。训练段由约 1.06 s 降至约 0.32 s（3 倍以上），推理内核未改动。C 版反传仍为标量循环，训练段约 0.70 s。两个版本的算法与模型相同，差异来自内核实现。

源码并排对比 SIDE BY SIDE

选取五个有代表性的部分，展示同一逻辑在两种语言中的写法。左侧为 C，右侧为 Zig。

Cexamples/gpt_names/c/microgpt.c · dot16（AVX2 版；NEON 还要再写一份）
static __attribute__((always_inline)) inline float dot16(const float *a, const float *b) {
  __m256 r = _mm256_fmadd_ps(_mm256_loadu_ps(a),   _mm256_loadu_ps(b),
             _mm256_mul_ps (_mm256_loadu_ps(a+8),  _mm256_loadu_ps(b+8)));
  __m128 lo = _mm256_castps256_ps128(r), hi = _mm256_extractf128_ps(r, 1);
  lo = _mm_add_ps(lo, hi); lo = _mm_hadd_ps(lo, lo); lo = _mm_hadd_ps(lo, lo);
  return _mm_cvtss_f32(lo);
}
Zigexamples/gpt_names/fp32.zig · dot16（一份源码，适用于 x86 与 ARM）
inline fn dot16(a: *const [16]f32, b: *const [16]f32) f32 {
    const va0: Vec8 = a[0..8].*;
    const vb0: Vec8 = b[0..8].*;
    const va1: Vec8 = a[8..16].*;
    const vb1: Vec8 = b[8..16].*;
    const p0 = va0 * vb0;
    const p1 = va1 * vb1;
    return @reduce(.Add, p0 + p1);
}
两段代码的数学相同。C 的水平求和需要手工组织 cast、extract 与 hadd 指令；Zig 使用 @reduce(.Add, …)，由 codegen 按目标宽度（AVX2 8-lane / NEON 4-lane×2）生成指令。

Zigexamples/gpt_names/fp32.zig · 文件头
const builtin = @import("builtin");

const is_x86 = builtin.cpu.arch == .x86_64;
const is_aarch64 = builtin.cpu.arch == .aarch64;
C 的 #ifdef 在预处理阶段做文本替换，宏内的错误要到展开并在对应架构上编译时才会暴露；Zig 的 builtin 是有类型的编译期值。由于内核与架构无关，这段代码只用于打印名称。代价：C 可在 AVX2 上使用 256-bit 指令、在 NEON 上安排 4-lane 寄存器，Zig 的统一源码不具备这种按架构调整的能力。
Cexamples/gpt_names/c/microgpt.c · 位技巧版 exp（跳过指数单元，精度换速度）
static __attribute__((always_inline)) inline float fexpf(float x) {
  union { float f; int i; } u;
  u.i = (int)(12102203.1615614f * x * 1.4426950408f) + 1065353216;
  return u.f;
}
Zigexamples/gpt_names/fp32.zig · 同一算法
inline fn fexpf(x: f32) f32 {
    const bits: i32 = @as(i32, @intFromFloat(12102203.1615614 * x * 1.4426950408))
                   + 1065353216;
    return @bitCast(bits);
}
union 型 punning 在 C 标准中属于实现定义行为（clang 与 gcc 均支持，但与 -fstrict-aliasing 同时使用存在风险）；Zig 的 @bitCast 由语言规定，f32 与 i32 的位重解释不需要 union。

Zigexamples/gpt_names/fp32.zig · 分配与释放
fn make_zero(size: usize) []f32 {
    const p = gpa.alloc(f32, size) catch {
        std.debug.print("out of memory\n", .{});
        clib.exit(1);
        unreachable;
    };
    @memset(p, 0);
    return p;   // 返回的是切片: ptr + len
}
/* ……程序结尾： */
gpa.free(wte);   // 长度信息在切片里，越界 Debug 可捕获
说明：Zig 版同样手动 free（使用 c_allocator 与 C 保持一一对应），未使用 arena。差别在于 C 的 float* 离开 calloc 后不再携带长度，需要调用方记录；Zig 的 []f32 切片包含长度，Debug 构建下越界访问触发 panic，ReleaseFast 不做检查。
Cexamples/gpt_names/c/microgpt.c · pack_t 转置打包
static void pack_t(const float *src, float *dst, int nout, int nin) {
  for (int r = 0; r < nout; r++)
    for (int c = 0; c < nin; c++)
      dst[(size_t)c * nout + r] = src[(size_t)r * nin + c];
}
Zigexamples/gpt_names/fp32.zig · pack_t 转置打包
fn pack_t(src: []const f32, dst: []f32, nout: usize, nin: usize) void {
    for (0..nout) |r| {
        for (0..nin) |c_idx| {
            dst[c_idx * nout + r] = src[r * nin + c_idx];
        }
    }
}
这段代码与 C 基本逐行对应，移植保持同构。区别：Zig 的 usize 避免了 (size_t) 强转与 int 溢出风险（负索引、混合符号比较为编译错误）；越界访问在 Debug 下触发 panic，未定义行为不会静默发生。

构建方式 BUILD

一条命令出两个二进制

$ zig build --release=fast
→ zig-out/bin/fp32-baseline.exe # Zig 版
→ zig-out/bin/microgpt-c.exe # C 版（A/B 对照）
$ zig build --release=fast run # 直接跑
$ make CC=gcc run # 老工具链对照
$ zig build --release=fast example-gpt # fp32 预训练 → 三元 QAT → 打包导出 全链路

build.zig 用 addCSourceFile 编译 C 版，flags 为 -Ofast -mavx2 -mfma -Wall。两个二进制由同一套 Zig/LLVM 工具链编译，以保证可比性。

仓库定位

项目主体使用 Zig（examples/gpt_names/fp32.zig 为主要实现），C 源码（examples/gpt_names/c/microgpt.c）作为参考实现，随每次构建编译，用于对照。本页为该对照结果的页面记录。

两个版本均为单文件、除 libc 外无外部依赖，使用同一算法（前向、反向、Adam、采样、权重打包、(token,pos) 表预计算、融合采样器）。

结论 VERDICT

结果说明
纯推理吞吐Zig +3.4%LLVM 为 @Vector 内核生成的调度更符合 Zen4 的 FMA 流水线
全流程耗时Zig −25%训练反传向量化后训练段约 0.32 s，低于按标量反传的 C（约 0.70 s）
数值行为相同同种子下 avg loss 相差 0.0005，首个样例即出现差异（舍入误差放大）
可维护性Zig1 套跨架构内核，C 为 2 套手工维护的内核；无预处理层
按架构调整的空间C寄存器分配与 lane 宽度可逐周期调整
开发期检查ZigDebug 下越界 panic、显式类型转换、编译期维度检查
结论：对需要精细调度的热路径内核，C 的 intrinsics 仍是可用的手段；若要用一份源码适配 x86 与 ARM 两种向量宽度，并保留编译期检查与 Debug 模式下的越界检查，Zig 的 @Vector 与类型系统可以减少维护量。本次训练路径向量化后，Zig 的推理吞吐与全流程耗时均高于 C 版。
