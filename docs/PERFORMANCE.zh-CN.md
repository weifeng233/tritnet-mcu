# 性能笔记

推理前向与训练前向有何不同，以及每个 token 的时间花在哪里。

## 推理路径

训练与推理使用两条独立的前向路径。`gpt_forward` 为反向传播保存每个
token 约 1.3 KB 的激活；`gpt_forward_infer` 完全不需要激活，并且是为逐
token 解码而专门构建的。其 logits 与训练前向在 AVX2 上相差 2.4e-06 绝对
值（logits 量级约 8），属于 fp32 舍入噪声。

一共有两个后端。权重打包、`(token, pos)` 表和采样器是共享的；只有内核与
前向主体不同。NEON 每次处理 4 个 float，AVX2 是 8 个，因此 AVX2 的矩阵-
向量乘所需指令减半：16 行块的一列只需一次广播加两条 FMA，而 NEON 需要 4
条按通道索引的 FMA。

推理路径做了这些不同的事：

- 列主序权重，矩阵-向量乘直接累加进输出寄存器，全程没有水平归约。
  `infer_pack_weights()` 在最后一次优化器更新之后一次性构建转置副本。
- 分组累加器。只有一组累加器会把矩阵-向量乘变成 `nin` 条 FMA 的串行链，
  因此 `mv16_blk16r` 用两组，而 fc1 调用的 `mv16_blk16r4` 用四组。
- 提取公共前缀。嵌入、两个 RMS 归一化和第 0 层的 Q/K/V 只依赖
  `(token, pos)`，而不同的输入只有 `vocab * BLOCK_SIZE` 种，所以
  `build_pretok()` 把它们放进一张表。
- 延迟 RMS 缩放。MLP 的归一化缩放是正标量，而 fc1/ReLU²/fc2 是正齐次的，
  因此 `rmsnorm_scale()` 把它返回出来，最后在 fc1 关键路径之外折算成一次
  `s^2`。非正齐次的激活会破坏这一点。
- 融合采样。`sample_logits()` 在未归一化权重上单趟完成 softmax、温度与
  加权选择。
- 词表只填充到 4 而非 16。`mv16_blk16`、`mv16_blk8` 和 `mv16_blk4` 分别
  发射 16/8/4 行的分块，因此 27 个 token 的词表花 28 行而不是 32 行。

## 时间花在哪里

约一半时间在 MLP。

瓶颈是指令发射宽度而非停顿。往 token 循环里加额外的独立 FMA，每条实测
0.20 周期，而理论下限是 0.19，所以没有空闲槽可填：机器是在忙，不是在
等。因此加速只能来自发射更少的指令，而不是更好的调度。

单线程，跑基准的 5M token 采样循环：

| 机器 | 后端 | tok/sec | |
| --- | --- | --- | --- |
| AMD Ryzen 9 7940H | AVX2 | 5,491,565 | 5 次运行取中位数 |

## 编译器

Zig 构建（`zig build --release=fast`）即 `ReleaseFast`（`-Ofast` 语义）。
在 AMD Ryzen 9 7940H 上，两个 zig 构建的二进制在运行间噪声内一致：
5.49M（zig fp32+AVX2）对 5.39M（c fp32+AVX2）tok/sec，均为 5M-token 循环
5 次运行的中位数。Makefile 仍默认 `zig cc`（Zig 的即插即用 clang）；同一
C 源码经 Makefile 构建实测 5.81M，gcc `-Ofast` 实测 5.23M —— zig 的
clang 快约 11%（各 5 次运行取中位数）。`make CC=gcc` 可复现 gcc 的数字。
这台机器的会话间漂移有几个百分点，所以请比较同一次测量会话内的数字。

AVX2 路径是两者中调得较少的。NEON 路径的每个常数都是在 ARM 硬件上 A/B
实测选出的，几乎没有在 x86 上复测过。注意一组累加器占 16 个 float，在
NEON 上是 4 个寄存器、4 条独立链，在 AVX2 上只有各 2 条：同一份源码到
x86 上链数减半。x86-64 的向量寄存器也只有 16 个（ARM64 是 32 个），这让
吃寄存器的选择最有可能藏着提升空间。

## 死胡同

实测过并放弃的方向，记录下来以免再试：

- fp16 权重。FMLAL（fp16 乘、fp32 累加）把权重字节减半但不减操作数，
  241 个周期里只挪动了 MLP 一个周期。连累加也用 fp16 确实把操作数减半
  并换来 5% 的提升，代价是 logits 精度掉了三个数量级。
- 牛顿迭代精化的倒数与 rsqrt，比硬件 `fdiv` 和 `fsqrt` 慢 2–4%，因为
  精化需要 5 条指令而硬件只要 1 条。
- AVX2 上更多的累加器链。把 Wo 和 lm_head 从 4 条链提到 8 条，在这台
  机器上实测持平。
- 打破 token 到 token 的依赖：回放一段录制的 token 轨迹，让相邻 token
  相互独立。没有更快，所以没有任何东西在等这个依赖。

批处理是能抬高天花板的变化。一次跑几条独立序列，会把每个矩阵-向量乘
变成矩阵乘，让权重获得它们目前完全没有的复用。

## 训练路径

训练循环（`gpt_forward`/`gpt_backward`/Adam）曾长期是标量的；严格的 FP
求值让 LLVM 无法向量化其中的归约和累加循环。现在它与推理路径用同一套
`@Vector` 风格，x86 和 NEON 上都是 8 宽内核：

- `linear_bwd_x` 顺序遍历行，每个权重列保持一组 8 宽累加器，而不是每个
  输出通道沿 `nout` 行跨步。每列的和保持行序，因此数值与标量版一致。
- `linear_bwd_w` 是逐行的 8 宽 FMA 外积。
- `adam_update` 是 8 宽的，偏差校正与裁剪系数作为参数传入。梯度裁剪折进
  Adam 的梯度读取（`g * scale`），而不是再来一遍重缩放并重写每个梯度
  数组的全量遍历。
- 梯度范数归约是对每个梯度数组一趟融合乘加完成。
- 注意力前向/反向用 `Vec4` FMA 对 kv 行累加 4 宽的头切片；残差加法、
  ReLU² 和嵌入/散点路径是 8 宽。
- 每步的固定开销：前向前的 kv 缓存重置是死代码（每个位置先写 k/v、再被
  注意力读取）；dk/dv 累加器的重置只覆盖 `n` 个活跃位置；Adam 的
  `pow(b1, step)` 偏差校正每步只算一次；`char_to_id` 是 256 项查找表。

7940H 上 ReleaseFast、对 `data/names.txt` 训 20000 步（5 次运行中位数）：
0.30 秒，约 6.7 万步/秒。最终平均损失 2.2194，标量版 2.2199 —— 数值上
仅有的变化是重结合的求和（向量通道拆分、新内核中的 FMA 收缩），采样结果
依然像人名。推理吞吐不受影响，因为其代码路径未动。训练计时器现在会在
最后一步之后打印 `train: <s> (<steps/sec>)`。
