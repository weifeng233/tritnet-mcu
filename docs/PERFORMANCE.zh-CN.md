# 性能分析

- **适用范围：** v0.2.0 的 `main`
- **最后验证：** 2026-10-30
- **验证命令：** 在下文标注的机器上运行 `zig build --release=fast run` 与 `zig build --release=fast example-gpt`

本文说明推理前向与训练前向的差异，以及每个 token 的耗时分布。

## 推理路径

训练与推理使用两条独立的前向路径。`gpt_forward` 为反向传播保存每个
token 约 1.3 KB 的激活；`gpt_forward_infer` 不保存激活，为逐 token
解码专门构建。其 logits 与训练前向在 AVX2 上的绝对值差为 2.4e-06
（logits 量级约 8），属于 fp32 舍入误差。

共有两个后端。权重打包、`(token, pos)` 表和采样器为共享代码，只有
内核与前向主体不同。NEON 每次处理 4 个 float，AVX2 为 8 个，因此
AVX2 的矩阵-向量乘所需指令减半：16 行块的一列只需一次广播加两条
FMA，NEON 需要 4 条按通道索引的 FMA。

推理路径的差异如下：

- 列主序权重：矩阵-向量乘直接累加进输出寄存器，全程没有水平归约。
  `infer_pack_weights()` 在最后一次优化器更新之后一次性构建转置副本。
- 分组累加器：若只使用一组累加器，矩阵-向量乘会形成 `nin` 条 FMA 的
  串行依赖链，因此 `mv16_blk16r` 使用两组，fc1 调用的 `mv16_blk16r4`
  使用四组。
- 提取公共前缀：嵌入、两个 RMS 归一化和第 0 层的 Q/K/V 只依赖
  `(token, pos)`，不同的输入只有 `vocab * BLOCK_SIZE` 种，因此
  `build_pretok()` 将它们预先计算并存入一张表。
- 延迟 RMS 缩放：MLP 的归一化缩放为正标量，fc1/ReLU²/fc2 为正齐次
  函数，因此 `rmsnorm_scale()` 将该缩放因子作为返回值传出，在 fc1
  关键路径之外折算为一次 `s^2` 乘法。非正齐次的激活不适用该变换。
- 融合采样：`sample_logits()` 在未归一化权重上单趟完成 softmax、温度
  与加权选择。
- 词表按 4 行粒度填充：`mv16_blk16`、`mv16_blk8` 和 `mv16_blk4` 分别
  发射 16/8/4 行的分块，27 个 token 的词表因此占用 28 行；若按 16 行
  粒度填充则需 32 行。

## 耗时分布

约一半时间消耗在 MLP。

瓶颈是指令发射宽度。在 token 循环中增加额外的独立 FMA 后，每条指令
实测占用 0.20 周期，理论下限为 0.19 周期，发射槽已无空闲。因此加速
只能来自减少发射的指令数量。

单线程，5M token 基准采样循环。两个二进制都来自 `zig build --release=fast`，
同一次会话（2026-10-30）内测量：

| 机器 | 后端 | tok/sec | 条件 |
| --- | --- | --- | --- |
| AMD Ryzen 9 7940H | Zig fp32，AVX2 | 8,441,952 | 5 次中位数，高性能电源方案 |
| AMD Ryzen 9 7940H | C fp32，AVX2 | 8,217,680 | 同一轮、同一编译参数 |

**电源方案的影响比本文任何优化都大。** 同样两个二进制在本机"平衡"方案下约
400 万 tok/sec，高性能方案下 840 万，相差约 2 倍。本文早先版本给出的
5,491,565 tok/sec 没有说明电源条件，2026-10-30 无法复现，因此换成本次实测并
记录条件，而不是给它找解释。

## 编译器

Zig 构建（`zig build --release=fast`）即 `ReleaseFast`（`-Ofast` 语义）。
在 AMD Ryzen 9 7940H 上，编译同一份 C 基线有三种方式，彼此相差几个百分点：
2026-10-30 一次会话中 5 次运行的中位数分别是 8.22M（`zig build`）、
7.92M（`make`，即 `zig cc`）、8.09M（`make CC=gcc`）。三者之间的差距
小于同一二进制在受限功耗笔记本上的运行间波动，所以"zig cc 快 11%"这种结论
换个会话就不成立。

稳定成立的是：Zig 与 C 基线在相同编译参数下相差约 3%，说明移植没有悄悄变慢。
比较时请取同一会话内的数据，并记录电源方案。

AVX2 路径的调优程度低于 NEON 路径。NEON 路径的每个常数均在 ARM
硬件上通过 A/B 实测选出，在 x86 上极少复测。一组累加器占 16 个
float，在 NEON 上为 4 个寄存器、4 条独立链，在 AVX2 上为 2 个寄存器、
2 条链：同一份源码在 x86 上链数减半。x86-64 的向量寄存器数量也只有
16 个（ARM64 为 32 个），寄存器占用最多的代码路径最可能存在优化
空间。

## 已放弃的优化方向

以下方向经实测后放弃，记录于此以避免重复尝试：

- fp16 权重。FMLAL（fp16 乘、fp32 累加）将权重字节减半但不减少
  操作数，241 个周期中 MLP 仅减少 1 个周期。累加同样改用 fp16 可将
  操作数减半并取得 5% 的提升，代价是 logits 精度降低三个数量级。
- 牛顿迭代精化的倒数与 rsqrt 比硬件 `fdiv` 和 `fsqrt` 慢 2–4%：精化
  需要 5 条指令，硬件实现只需 1 条。
- AVX2 上更多的累加器链。将 Wo 和 lm_head 从 4 条链增加至 8 条，在
  该机器上实测性能持平。
- 打破 token 间的依赖：回放一段录制的 token 轨迹，使相邻 token 相互
  独立。实测无速度提升，表明执行未受该依赖限制。

批处理可以提高吞吐上限。一次处理多条独立序列时，每个矩阵-向量乘
变为矩阵乘，权重得以复用；当前逐 token 路径中权重没有复用机会。

## 训练路径

训练循环（`gpt_forward`/`gpt_backward`/Adam）此前为标量实现；严格的
浮点求值语义使 LLVM 无法向量化其中的归约和累加循环。现在训练循环
与推理路径使用同一套 `@Vector` 风格，x86 和 NEON 上均为 8 宽内核：

- `linear_bwd_x` 顺序遍历行，为每个权重列维护一组 8 宽累加器（未按
  输出通道沿 `nout` 行跨步累加）。每列的和保持行序，因此数值与标量
  版一致。
- `linear_bwd_w` 为逐行的 8 宽 FMA 外积。
- `adam_update` 为 8 宽实现，偏差校正与裁剪系数作为参数传入。梯度
  裁剪合并进 Adam 的梯度读取（`g * scale`），避免对每个梯度数组再做
  一次全量重缩放遍历。
- 梯度范数归约对每个梯度数组以一趟融合乘加完成。
- 注意力前向/反向以 `Vec4` FMA 对 kv 行累加 4 宽的头切片；残差加法、
  ReLU² 和嵌入/散点路径为 8 宽。
- 每步的固定开销：前向前的 kv 缓存重置为死代码（每个位置先写 k/v、
  再被注意力读取）；dk/dv 累加器的重置只覆盖 `n` 个活跃位置；Adam
  的 `pow(b1, step)` 偏差校正每步只计算一次；`char_to_id` 为 256 项
  查找表。

7940H 上 ReleaseFast、对 `data/names.txt` 训练 20000 步（5 次运行中位
数）：耗时 0.30 秒，约 6.7 万步/秒。最终平均损失 2.2194，标量版为
2.2199 —— 数值差异仅来自求和的重结合（向量通道拆分、新内核中的
FMA 收缩），采样生成的结果仍为人名。推理吞吐不受影响，其代码路径
未改动。训练计时器在最后一步之后打印 `train: <s> (<steps/sec>)`。
